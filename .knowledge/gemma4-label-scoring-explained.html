The Gemma Lab
how a label gets its score

SigLIP2 measures. Gemma looks and writes a number down. This is a playable lab: feed it frames and labels, watch the real sampling pipeline run (with a transparent stand-in for the model’s judgement), and learn why the “best-fitted” label is just the one Gemma scores highest.

google/gemma-4-E2B-it semantics: verbalized · uncalibrated runs offline · zero network
01

Two very different ways to score

Same question — “how well does this label fit?” — two machines. Knowing which page you’re on changes how you read the numbers.

/ · the SigLIP2 page

It measures

  • Encodes image and text into vectors, takes their similarity.
  • A sigmoid turns similarity into 0–1, per label.
  • A real, repeatable computation over embeddings.
  • Calibrated enough to compare across runs; threshold 0.5.
/gemma · this page

It reads & reports

  • Sees the actual frames + your labels as one prompt.
  • Generates a JSON array — literally writes a number per label.
  • The score is a verbalized self-report: judgment, not arithmetic.
  • Uncalibrated & quantized. Read it as a ranking, not a probability.
✦
Because the score is generated text, the whole “calculation” is a prompt + a decode loop + a strict parser. The Lab below runs every stage of it on a real (illustrated) clip.

06
What the winning score actually means

    
A ranking signal, not a probability. Each behavior is rated for how strongly it’s visible anywhere, so the scores don’t form a distribution and won’t sum to 1. Two labels can both read 0.8; none has to. (This is not the same as “scored independently” — see below.)

    
Quantized and uncalibrated. Generative models gravitate to round numbers — 0.0, 0.5, 0.8 — so treat values as ordinal: higher beats lower, but the 0.7→0.8 gap isn’t a precise 0.1 of anything. A Gemma 0.8 is not comparable in magnitude to a SigLIP2 0.8.

    
Implicitly contrastive. The model sees every label at once in one prompt, so its scores are quietly relative to the set you submit. Change the label list and the numbers can shift. Real Gemma judges the labels jointly — it does not score them independently. (This site’s teaching stand-in does score independently, by construction; that’s the one thing it can’t imitate, and the flashcards say so.)

    

      
Score semantics — gemma4_verbalized_uncalibrated

      Scores are verbalized self-reports from a generative model: uncalibrated, quantized to round numbers, and implicitly contrastive across labels. Treat as ordinal. NOT comparable in magnitude to SigLIP2 sigmoid scores. Not suitable for safety-critical decisions.

      Good to know at the edges
      

        

          
SituationWhat happens

          
            
Model omits a label idThat label’s score becomes null → rendered n/a, not zero. (The model violated “include every id exactly once”; the strict parser tolerates it.)

            
Very short windowThe 0.5s spacing floor caps N below 8 — a 3s window yields int(3/0.5)=6 frames — so you never get redundant near-identical frames.

            
Malformed JSONProse around the array is sliced off; a genuinely bad parse buys exactly one retry, then a 502.

            
Window past clip endwindow_start ≥ duration is rejected before any work starts.

            
Slot not warmedScoring returns 503 (middleware pre-body gate) until POST /api/v1/gemma/warm finishes. Load-once, then resident.

            
Request runs longSoft deadline checked between decode steps; max_new_tokens is the real bound. Response carries per-stage latency + retry count.
